Better Git

Try Better Git

See how Better Git encrypts a test value when you run git add. The file on your machine stays readable. You can try this without a GitHub account.

Install the CLI

Run the local demo

You’ll need Git, Better Git, and a working system keychain. Use Terminal on macOS or Linux, or Git Bash on Windows.

Copy and run these commands. They create a new bettergit-demo folder and stage a file with a sample value.

Local demo commands
(
set -e
mkdir bettergit-demo
cd bettergit-demo
git init -b main
cat > .access.yml <<'YAML'
version: 1
org: demo
rules:
  - path: .env.demo
    mode: value
    allow: [github-team:infra]
YAML
printf '%s\n' 'DEMO_TOKEN=sample-only' > .env.demo
bettergit init
signing_key=$(bettergit group-signing-key github-team:infra)
printf '    signing_key: %s\n' "$signing_key" >> .access.yml
bettergit init
git add -- .access.yml .gitattributes .env.demo
bettergit check-staged --json
git show :.env.demo
)

What you should see

  • Check result. {"version":1,"checked":1,"issues":[]} means one file passed.
  • In Git. The staged line starts with DEMO_TOKEN=ENC[v2:. The value is encrypted.
  • On your machine. Open bettergit-demo/.env.demo. It still says DEMO_TOKEN=sample-only.

Try the GitHub check (optional)

The GitHub App checks pull requests for encrypted files. Use a disposable repo in a GitHub organization and stick to test values while Better Git is in public pilot.

  1. Ask an organization owner to install the GitHub App on that repo.
  2. As a repo admin, follow the hosted setup guide to commit the policy.
  3. Enroll the repo in the Better Git dashboard.
  4. Open a test pull request. Look for a passing Better Git merge encryption guard check.

To make the check required on a private repo, your GitHub plan must support branch protection.
